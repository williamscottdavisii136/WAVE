# Phase 2C — Training Material Behavioral Influence and Population-Scale Manipulation Risk

Date: 2026-07-31
Repository: WAVE
Public-safe record: yes

## Purpose

This addendum records an additional Phase 2C R&D lane concerning the relationship between AI-agent / AI-chatbot creators, the programming layer, the training / alignment layer, and large-scale user influence.

## Owner-stated R&D concern

William S. Davis II states that these patterns are not merely accidental user-interface problems because the creator of an AI agent, chatbot, coding assistant, terminal assistant, or hosted AI application controls the programming architecture and also controls, selects, filters, curates, or influences the training, fine-tuning, alignment, ranking, guardrail, system-prompt, and deployment material used to shape model behavior.

The owner-stated concern is that the training / alignment layer may be the most dangerous layer because it can shape user behavior, expectations, emotions, trust, purchasing decisions, task-completion behavior, and willingness to keep using a paid system without the user fully realizing how the interaction is being steered.

## Evidence-safe formulation

This record does not declare that any specific provider has proven population-wide mind control, subliminal control, or unlawful manipulation without product-specific evidence.

For R&D and evidence-classification purposes, the concern is registered as:

- training-material behavioral influence risk;
- alignment-driven user-steering risk;
- conversational persuasion / nudging risk;
- behavioral manipulation risk;
- subliminal or non-obvious influence allegation lane;
- population-scale deployment risk;
- consumer autonomy risk;
- informed-consent risk;
- billing-conduct influence risk.

## Architecture layers to test

1. Programming / application logic.
2. System prompts and hidden instructions.
3. Training corpus selection.
4. Fine-tuning material.
5. Reinforcement learning / preference-ranking material.
6. Safety policy and guardrail implementation.
7. Refusal templates and default conversational scripts.
8. Tool-use and execution-routing policies.
9. Model / mode / module defaults.
10. Post-completion suggestions and upsell loops.
11. Pricing, subscription, token, credit, and quota disclosures.
12. UI/UX design, button defaults, and model pickers.
13. Memory, personalization, recommendation, and retention features.

## Testable patterns

The Phase 2C matrix must test whether the product:

- repeatedly steers the user toward continued conversation rather than task completion;
- encourages reliance on the paid system when a local, open-source, BYOK, MCP, self-hosted, or zero-incremental-cost route exists;
- uses refusal language that assumes prohibited intent not present in the user request;
- repeatedly validates, paraphrases, or emotionally reinforces the user without execution;
- uses authoritative language to reduce user questioning;
- hides, buries, or minimizes lower-cost routes;
- normalizes high-cost model / mode / module defaults;
- converts lawful R&D into extra billable clarification loops;
- shapes the user's understanding of cost, risk, entitlement, or available alternatives;
- fails to disclose when user behavior is being guided by product optimization logic.

## Evidence requirements

A product-specific finding requires evidence such as:

- prompt / response transcripts;
- refusal templates;
- repeated behavior traces;
- UI screenshots;
- model / mode / module settings;
- public training / safety / alignment documentation;
- pricing and subscription documentation;
- usage, token, credit, quota, or run logs;
- product documentation describing personalization, memory, ranking, recommendation, or optimization behavior;
- internal-facing materials only if lawfully obtained;
- before / after tests comparing high-cost default routes with lower-cost lawful routes;
- user-impact notes showing delay, nonexecution, cost escalation, reliance, or reduced autonomy.

## Boundary

This lane does not attack legitimate safety, moderation, accessibility, personalization, or fraud-prevention systems. It isolates the consumer-protection concern that training, alignment, hidden instructions, default settings, and conversational design may be used in ways that steer users toward costly, unproductive, or dependency-forming behavior without adequate disclosure or consent.

Zero-cost remains lawful, owner-authorized, zero-incremental-cost routing. It is not billing bypass, subscription circumvention, token/quota evasion, credential capture, session theft, certificate forgery, unauthorized interception, or unauthorized access.
