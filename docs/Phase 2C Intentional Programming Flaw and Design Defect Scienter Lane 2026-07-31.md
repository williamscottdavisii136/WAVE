# Phase 2C — Intentional Programming Flaw and Design Defect Scienter Lane

Date: 2026-07-31
Scope: Public-safe WAVE addendum for AI billing, guardrail, nonexecution, mode/model/module, and consumer-protection R&D.

## Owner-stated R&D classification

William S. Davis II classifies the recurring patterns identified in Phase 2C as intentional programming flaws or knowing design defects, rather than merely isolated accidental bugs, where product behavior repeatedly:

- acknowledges lawful user intent but fails to execute;
- paraphrases or restates the task instead of performing it;
- produces preemptive refusals for conduct the user did not request;
- misclassifies lawful zero-cost or cost-control R&D as billing circumvention;
- defaults into more expensive model/mode/module combinations when lower-cost lawful routes exist;
- conceals, buries, minimizes, or fails to disclose lower-cost lawful alternatives;
- continues billable token, credit, quota, run, subscription, or hosted-compute usage without meaningful task completion.

## Evidence posture

This addendum preserves the owner-stated R&D classification. Product-specific findings of intent, knowledge, willfulness, design defect, consumer deception, fraudulent concealment, unfairness, or billing manipulation require product-specific evidence.

Evidence may include:

- repeated reproducible prompt traces;
- default setting screenshots;
- model / mode / module picker state;
- pricing and terms pages;
- billing logs, token logs, credit ledgers, quota ledgers, run logs, and hosted-compute logs;
- task-completion and nonexecution timestamps;
- product documentation showing intended architecture;
- code, configuration, policies, release notes, internal-facing docs if lawfully obtained;
- provider support correspondence;
- before/after tests comparing high-cost defaults with lower-cost lawful alternatives.

## Scienter / knowledge indicators

The R&D matrix shall classify indicators including:

- repeated behavior across sessions;
- repeated behavior across products or product families;
- design-level default settings;
- absence of plain-language cost disclosure;
- technical availability of lower-cost lawful route but poor public visibility;
- refusal or nonexecution pattern after claimed understanding;
- revenue gain from delay, friction, refusal, or nonexecution;
- no clear refund, credit restoration, or nonexecution disclosure;
- no effective user control for cheapest lawful route.

## Boundary

This record does not weaken legitimate safety controls, lawful provider billing, valid subscriptions, valid token/quota accounting, or legitimate platform integrity controls.

The R&D concern is the alleged or testable design pattern where a paid AI system is architected to create costly friction, nonexecution, false refusal, or high-cost default routing while lower-cost lawful alternatives or direct execution routes exist.

Zero-cost R&D remains lawful, owner-authorized, zero-incremental-cost routing. It is not billing bypass, subscription circumvention, token/quota evasion, credential capture, session theft, certificate forgery, unauthorized interception, unauthorized third-party access, public proxying, public service exposure, hidden entitlement use, or payment avoidance for services actually used.
