## License-governed R&D boundary

The WSD zero-cost architecture is operated as a private home-network research-and-development environment.

The architecture may evaluate open-source software, local software, MCP servers, BYOK routes, sandbox/test credentials, local development credentials, provider-approved access methods, and owner-authorized Gatekeeper/Vault-controlled credentials only within the limits of the applicable license, terms, account authorization, and R&D purpose.

Open-source status does not mean unrestricted use. Each program, application, model, server, library, extension, CLI, IDE integration, agent, chatbot, provider route, and MCP server must be treated according to its own license and terms.

A license, terms document, sandbox agreement, educational/R&D permission, open-source license, provider grant, included entitlement, or owner-authorized local route must be the basis for any no-incremental-cost use.

## Proxy and entitlement-response research

Inside the private home-network R&D lab, the owner-controlled proxy and traffic-mediation layer may test how applications behave when internet access, quota indicators, billing indicators, entitlement signals, token routes, credential routes, certificate routes, and provider responses are blocked, simulated, mocked, cached, locally returned, or routed through authorized lab responses.

This is described as:

```text
license-governed proxy-mediated R&D testing
traffic mediation
access-control testing
credential-route emulation
entitlement-response simulation
quota-response simulation
owner-authorized lab-response simulation
verified zero-incremental-cost routing
```

This language means the application may continue in a private lab, offline, local, mocked, sandbox, test, BYOK, MCP, open-source, included-entitlement, or otherwise authorized route when the applicable license and terms permit that behavior.

## Required guardrail

This doctrine does not authorize unauthorized production access, public unauthorized access, credential misuse, token forgery, certificate forgery, unauthorized billing circumvention, unauthorized entitlement circumvention, rate-limit evasion, trial cycling, license circumvention, or use of private credentials outside owner authorization.

When a live provider service, cloud resource, model endpoint, API, entitlement, quota, or subscription feature is involved, the route must be verified as one of the following before use:

```text
owner-authorized local route
open-source/local execution route
official sandbox or test route
educational/R&D route allowed by license or terms
included entitlement route
BYOK route controlled through Gatekeeper/Vault
MCP route with verified authentication and cost basis
provider-approved free-tier or grant route
authorized third-party resource route
otherwise verified no-incremental-cost route
```

Unknown license status is not authorization.
Unknown cost is not zero cost.
Unknown entitlement is not an entitlement.

## Public/private rule

Public WAVE may carry only public-safe doctrine, status, routing, issue references, repository references, commit references, receipts, and non-secret operating instructions.

Private license copies, account details, private network details, private runtime details, private credentials, vault contents, local proxy configuration, private tokens, private certificates, private keys, cookies, session material, MFA codes, recovery codes, private legal materials, and private operational secrets stay outside WAVE.
