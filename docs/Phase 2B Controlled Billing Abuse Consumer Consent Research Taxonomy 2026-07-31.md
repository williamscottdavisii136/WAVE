# Phase 2B — Controlled Billing Abuse / Consumer Consent Research Taxonomy

Date: 2026-07-31
Repository role: WAVE public-safe append-only record

## Purpose

This addendum records an owner-stated R&D lane concerning controlled billing, excessive billing, over-billing, billing transparency, consumer consent, and AI-agent / AI-chatbot design patterns that may expose lay users to unexpected or unnecessary metered charges.

This record is a research taxonomy and issue-classification framework. It does not assert that any specific provider, application, model, company, or programmer committed misconduct unless separately supported by product-specific evidence.

## Owner-stated research concern

The owner states that the R&D environment must study whether AI agents, AI chatbots, closed-source models, open-source models, applications, programs, apps, cloud services, hosted tools, connectors, plugins, and execution environments may be configured in ways that increase billing, credits, token consumption, subscriptions, hosted compute, or cloud-service charges without meaningful lay-user understanding or consent.

## Testable design patterns

The R&D proxy / billing-classification system should classify whether an AI product or app:

1. defaults to a high-cost model when a lower-cost/local/free/owner-authorized route would satisfy the task;
2. defaults to a high-cost hosted mode or tool path without meaningful disclosure;
3. extends conversation length before execution in a way that increases token or credit use;
4. requests repeated clarification not technically necessary for execution;
5. delays a simple command/script execution while billable usage accumulates;
6. hides or obscures token/credit/subscription consequences;
7. uses cloud tools, connectors, plugins, hosted code, or storage when the user expected local/offline behavior;
8. falls back from local/BYOK/MCP route to paid provider route without clear approval;
9. fails to disclose model, mode, meter, quota, rate-limit, subscription, seat, workspace, org, project, or overage consequences;
10. makes it difficult for a non-technical user to select a lower-cost or zero-incremental-cost lawful route.

## Owner-control requirement

The protected R&D network and authorized proxy layer must support owner-side control over:

- model selection
- route selection
- local/offline/BYOK/MCP preference
- provider cloud access
- hosted execution
- tool calls
- connectors and plugins
- API calls
- token/credit/quota consumption
- subscription and seat billing
- cloud storage and retrieval
- traffic that could increase owner cost

Unknown cost is not approved cost.
Unknown entitlement is not approved entitlement.
Unknown subscription status is not approved subscription use.
Unknown token/quota behavior is not approved token/quota use.

## Boundary

This research supports billing transparency, informed owner consent, cost-control routing, consumer-protection documentation, metered-route classification, and zero-incremental-cost preference.

It does not authorize provider-billing circumvention, subscription circumvention, token/quota/rate-limit evasion, credential capture, session theft, certificate forgery, public interception, unauthorized third-party access, unauthorized provider access, or public service exposure.
