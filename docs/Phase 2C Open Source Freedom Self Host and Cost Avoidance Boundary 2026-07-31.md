# Phase 2C Open Source Freedom, Self-Host, and Cost-Avoidance Boundary

Date: 2026-07-31
Repository: WAVE public-safe record
Phase: 2C
Record type: append-only public-safe addendum

## Owner-stated correction

William S. Davis II clarifies that the R&D does not treat every AI provider, agent, chatbot, model, or application as engaging in revenue-optimizing conduct.

A central distinction exists between:

1. closed-source or hosted paid systems that may create billing, subscription, token, quota, hosted-compute, or revenue-optimizing default risks; and
2. open-source, self-hosted, user-controlled, lawful local systems that exist to preserve user freedom, inspectability, modification rights, portability, and cost avoidance.

## Open-source control principle

Open-source and user-controlled software must be treated as a baseline/control group for the R&D because it may allow the owner to:

- inspect source behavior;
- modify routing and execution behavior;
- self-host where permitted by license;
- avoid vendor lock-in;
- avoid unnecessary hosted execution;
- use local hardware already owned by the user;
- select lower-cost or zero-incremental-cost routes;
- preserve privacy and security inside the owner-controlled R&D network; and
- prevent unapproved billing escalation.

## Cost boundary

Open source does not automatically mean zero cost.

The R&D must distinguish:

- local open-source code running on owner-controlled hardware;
- open-source models running locally under valid license terms;
- BYOK / MCP / local gateway routes using owner-authorized credentials or accounts;
- open-source code wrapped by paid hosted APIs;
- open-source agents connected to paid cloud execution;
- open-source chatbots attached to subscription plans;
- open-source projects using paid connectors, hosted storage, marketplace services, or metered provider control planes.

## R&D implication

When a lower-cost open-source, self-hosted, local, BYOK, MCP, or owner-controlled route can perform the same practical task as a higher-cost hosted route, the R&D must evaluate:

- whether the user was shown the lower-cost route;
- whether the lower-cost route was technically available;
- whether the higher-cost route was selected by default;
- whether model/mode/module choice increased billing without commensurate performance gain;
- whether the user gave informed consent to the costlier route; and
- whether the product design favored revenue over user cost control.

## Boundary

This addendum does not assert provider-specific misconduct without evidence. It preserves the corrected distinction between open-source freedom / self-hosting / user control and paid hosted systems that require billing scrutiny.

No secrets, credentials, tokens, certificates, session material, IP addresses, MAC addresses, private SSIDs, private account identifiers, serial numbers, IMEIs, or local device identifiers are included.
